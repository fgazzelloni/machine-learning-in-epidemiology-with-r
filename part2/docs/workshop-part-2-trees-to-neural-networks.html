1. Workshop concept

The first workshop introduced the foundations of machine learning, starting with:

[ y=wx+b ]

Participants explored how a model learns, how gradient descent adjusts parameters, and how loss decreases during training. We also introduced the transition from base R to mlr3.

Part II should move from understanding how learning works to implementing and comparing machine-learning models on epidemiological data.

This time, we will follow the practical examples in the reference article more closely, using mlr3 for machine-learning workflows and Keras for neural networks.

The central question becomes:

How do different machine-learning algorithms learn from the same epidemiological data, and how can we compare their predictive performance?

The workshop should demonstrate three ideas:

  1. Different algorithms learn differently. Decision trees learn splitting rules, random forests combine trees, and neural networks learn weights through gradient-based optimisation.
  2. Training performance is not enough. Models must be evaluated on unseen observations using appropriate performance measures.
  3. Prediction and interpretation are different objectives. A model can predict disease accurately without identifying its causes.

2. Learning objectives

By the end of the workshop, participants should be able to:

  • Define an epidemiological classification task using mlr3.
  • Train decision trees and random forests.
  • Build and train a simple neural network with Keras.
  • Understand neural-network layers, activation functions, epochs and batch sizes.
  • Visualise neural-network training and validation loss.
  • Evaluate models using the same test observations.
  • Compare accuracy, sensitivity, specificity and ROC/AUC.
  • Understand overfitting and the role of cross-validation.
  • Interpret model results without confusing prediction with causation.

I would avoid introducing too many additional algorithms. The value of this second workshop is in following a complete and consistent modelling workflow, rather than expanding the number of methods covered.

3. Two-hour workshop programme

I recommend using the same heart-disease dataset as the article, rather than West Nile or Ebola for this second session.

The authors use 270 observations and 13 predictors, with heart disease present or absent as the binary outcome. Their examples use R, mlr3, decision trees and Keras, and they provide a companion code repository. This gives us a reproducible starting point and allows participants to follow the paper directly.

4. The practical workflow

Step 1 — Start with the article’s data

Use the authors’ preprocessing and dataset definitions wherever possible.

The companion repository is:

https://github.com/bips-hb/epi-handbook-ml

The prediction problem is:

[ P(X) ]

where (X) represents the available patient characteristics.

Participants should first examine the outcome distribution, predictors, missing values and class balance.

Before fitting any model, we establish a common training/test split.

All three models must use the same training and test observations. Otherwise, their performance estimates are not directly comparable.

Preprocessing operations that learn from data, such as scaling or imputation, must be estimated on the training data only.

Step 2 — Decision trees with mlr3

We begin with a classification tree because its learning process is relatively easy to visualise.

library(mlr3)
library(mlr3learners)

tree <- lrn(
  "classif.rpart",
  predict_type = "prob"
)

tree$train(task, row_ids = train_ids)

prediction_tree <- tree$predict(
  task,
  row_ids = test_ids
)

Here, task is the classification task created from the prepared heart-disease data.

The teaching question is:

What does the tree learn?

Unlike linear regression, it does not learn a slope and intercept. It learns splitting variables, thresholds, terminal nodes and their predictions.

The article also provides examples of tree visualisation and pruning, so we can reproduce these rather than introduce unrelated code.

Step 3 — Random forests

We then introduce ensemble learning.

forest <- lrn(
  "classif.ranger",
  predict_type = "prob",
  num.trees = 200
)

forest$train(task, row_ids = train_ids)

prediction_forest <- forest$predict(
  task,
  row_ids = test_ids
)

The conceptual progression is:

One tree → many trees → aggregated predictions

The main question is whether combining trees improves predictive performance on unseen observations.

This also introduces the trade-off between predictive performance and interpretability.

Step 4 — Neural networks with Keras

This is the central section of Part II.

We return to the concepts introduced in September:

[ y=wx+b ]

In Part I, we learned two parameters.

In Part II, we build a network containing multiple layers and many trainable parameters.

For binary classification, a simple network might look like:

library(keras3)

model <- keras_model_sequential(input_shape = c(n_features)) |>
  layer_dense(
    units = 16,
    activation = "relu"
  ) |>
  layer_dropout(rate = 0.2) |>
  layer_dense(
    units = 8,
    activation = "relu"
  ) |>
  layer_dense(
    units = 1,
    activation = "sigmoid"
  )

We then compile the model:

model |> compile(
  optimizer = optimizer_adam(
    learning_rate = 0.001
  ),
  loss = "binary_crossentropy",
  metrics = c("accuracy")
)

This is where the first workshop becomes directly relevant.

Participants already know what a loss function and optimiser are. Now they see how those components are used to train a neural network.

The network can then be trained:

history <- model |> fit(
  x_train,
  y_train,
  epochs = 50,
  batch_size = 16,
  validation_split = 0.2,
  verbose = 0
)

Here, x_train must be a numeric predictor matrix and y_train a binary numeric target. Categorical variables need suitable encoding, and numeric scaling should be fitted on training data only.

The code above is an illustrative keras3 implementation, not a claim that these are the article’s exact architecture or hyperparameters. We should reproduce the authors’ specific configuration in the final workshop materials.

5. The key demonstration: watching a neural network learn

This should be the most memorable part of the session.

In Part I, participants watched a regression line move as gradient descent adjusted two parameters.

In Part II, they will see the same general principle applied to a neural network.

Keras records the training history, allowing us to plot the evolution of loss and accuracy.

plot(history)

I would also prepare a customised ggplot2 visualisation showing training and validation loss across epochs.

The questions to ask participants are:

What happens when training loss decreases but validation loss starts increasing?

Does a larger number of epochs necessarily produce a better model?

How do the learning rate and batch size influence training?

This is where we introduce overfitting and early stopping, using the actual training curves rather than only theoretical explanations.

6. Compare the three models

The final practical exercise should compare the models using a common evaluation framework.

Model What does it learn? Main advantage Main limitation
Decision tree Splitting rules Easy to explain Can be unstable
Random forest An ensemble of trees Often strong predictive performance Less transparent
Neural network Weights and biases Flexible nonlinear relationships More training choices and potentially harder to interpret

The comparison should include ROC/AUC, sensitivity, specificity and accuracy.

We should also discuss the uncertainty associated with performance estimates, particularly because the heart-disease dataset contains only 270 observations.

For a dataset this small, a neural network is not automatically preferable to a tree-based model.

That is an important result in itself: more complex does not necessarily mean better.

For the live exercise, we can use one held-out test set for a simple demonstration. For a more defensible model comparison, we should use repeated or stratified cross-validation, with preprocessing and any hyperparameter tuning contained within the resampling procedure.

Common test-set evaluation

Run after completing the numeric-matrix setup and fitting the network. Use a prespecified threshold of 0.5 for this teaching comparison; do not choose it using test outcomes.

measures <- msrs(c(
  "classif.acc", "classif.sensitivity",
  "classif.specificity", "classif.auc"
))
tree_scores <- prediction_tree$score(measures)
forest_scores <- prediction_forest$score(measures)
nn_prob <- as.numeric(predict(model, x_test))
stopifnot(length(nn_prob) == length(test_ids))
truth <- as.integer(task$truth(rows = test_ids) == positive_class)
nn_class <- as.integer(nn_prob >= 0.5)
nn_scores <- c(
  classif.acc = mean(nn_class == truth),
  classif.sensitivity = mean(nn_class[truth == 1] == 1),
  classif.specificity = mean(nn_class[truth == 0] == 0),
  classif.auc = as.numeric(pROC::auc(
    pROC::roc(truth, nn_prob, levels = c(0, 1),
              direction = "<", quiet = TRUE)
  ))
)
comparison <- rbind(
  Tree = tree_scores, Forest = forest_scores, Neural_network = nn_scores
)
comparison

Check that both classes occur in the test set. No model scores or learning curves are asserted here. Reserve the test set for final evaluation; use training/validation data for architecture, stopping and threshold decisions.
